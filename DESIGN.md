# Архитектурные решения (DESIGN.md)

## 1. Механизм отмены устаревших запросов (`AbortController`)
При быстром вводе текста возникает состояние гонки (Race Condition): ответ на более ранний короткий запрос (например, `sp`) может вернуться от сервера позже, чем ответ на последующий уточненный запрос (`spain`).

**Почему выбран `AbortController`, а не флаг актуальности:**
* Простой булевый флаг или сравнение `query === currentQuery` лишь игнорируют результат постфактум. При этом браузер продолжает держать открытым сетевое соединение, скачивать потенциально большой JSON-ответ и парсить его в памяти, расходуя трафик и ресурсы CPU.
* При использовании `AbortController` вызов `controller.abort()` при каждом событии `input` (до срабатывания таймера `debounce`) физически разрывает HTTP-соединение на уровне браузера.
* Таймауты реализованы через композицию сигналов `AbortSignal.any([callerSignal, AbortSignal.timeout(8000)])`. В блоке `catch` разделяются пользовательская отмена (`DOMException` с `name === 'AbortError'`, которая тихо игнорируется) и таймаут (`name === 'TimeoutError'`, который отображается пользователю с кнопкой «Повторить»).

## 2. Обоснование задержки `debounce` (350 мс)
* **Если убрать задержку (0 мс):** При вводе слова из 7 букв приложение создаст 7 сетевых запросов и 6 немедленных отмен, что создает лишнюю нагрузку на API и дергает индикатор загрузки на каждый символ.
* **Если сделать задержку слишком большой (например, 1000+ мс):** Интерфейс будет ощущаться «заторможенным» — пользователь напечатает слово и будет вынужден целую секунду смотреть на пустой экран до появления спиннера.
* **Выбранное значение (350 мс):** Средний интервал между нажатиями клавиш при обычной печати составляет 150–250 мс. Пауза в 350 мс позволяет дождаться окончания ввода слова или слога, отправляя только один целевой запрос без ощутимой задержки для пользователя.

## 3. Оценка алгоритмической сложности (Big O)
* **`mapCountryResponse(raw)`:** Временная сложность — **$O(L + C)$**, где $L$ — количество официальных языков страны, $C$ — количество валют (на практике $L, C \le 15$, поэтому сложность стремится к константной **$O(1)$**). Пространственная сложность — **$O(L + C + B)$** для создания массивов языков, валют и границ ($B$).
* **Кэш и дедупликация запросов (`Map`):** Поиск готового результата в кэше (`this.cache.get`) и проверка активного промиса в полете (`this.inFlight.get`) выполняются за амортизированное константное время **$O(1)$**. Пространственная сложность кэша — **$O(K \cdot M)$**, где $K$ — количество уникальных поисковых запросов, $M$ — средний размер массива стран в ответе.

## 4. Применение принципов чистого кода
* **Single Responsibility Principle (SRP):** Логика разделена по независимым модулям:
  * `src/api/searchCountries.ts` — только сетевой слой и маппинг HTTP-статусов.
  * `src/api/CountrySearchController.ts` — управление жизненным циклом запроса, отменой, таймаутами и кэшированием без привязки к DOM.
  * `src/utils/mapCountryResponse.ts` — чистая функция трансформации данных.
  * `src/ui/render.ts` — исключительно манипуляции с DOM-деревом без сетевой логики.
* **DRY (Don't Repeat Yourself):** В `src/ui/render.ts` выделена вспомогательная фабрика `createEl` для типизированного создания DOM-элементов и установки классов/текста без дублирования шаблонного кода.
* **KISS и YAGNI:** Приложение собрано на нативных ES-модулях через `tsc` без тяжелых фреймворков и бандлеров, решая ровно поставленную задачу.
